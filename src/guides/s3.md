This app is an object storage that speaks the S3 protocol, the language almost every backup tool understands. A backup tool sends files to a **bucket** (a top-level folder), signs every request with a **key** (an access key and its secret, like a user name and a password), and talks to an **endpoint** (the address below) in a **region** (here `{{region}}`, a name the signature needs, nothing to do with geography). Use **path-style addressing**: the bucket goes after the address (`{{endpoint}}/bucket`), never in front of it as `bucket.host`. Give every machine or site its own bucket and its own key that can reach only that bucket. With versioning on the bucket, a machine that is broken into can overwrite or delete its files, but every earlier version stays in the bucket for the number of days you choose below: that is how long you have to notice and bring them back. Every example already holds this server's address for the place chosen above; the parts you replace are marked like `PASTE-SECRET-KEY-HERE`, and secrets always go into a file only you can read, never on a command line.

{{if no_internet}}
> **Warning:** this app has no internet address. A website hosted elsewhere, a phone away from home or a server in a data centre cannot reach it. Give it one (its page in ServApps, "Internet…"), or back such machines up through a machine at home.
{{end}}

## Before the first backup {#before admin}

Do this once per thing you back up (a server, a website, a phone): a bucket, a key that can reach only that bucket, versioning and a lock so that old versions stay, a rule that clears old versions so the disk does not fill, and a size limit. Never give the administrator's key to a machine or a website.

**Choose the number of days first** (30 below). It is the time you have to notice that a machine was broken into: a stolen key can replace or delete every file, the bucket keeps the earlier versions, and the rule below removes an earlier version that many days after it was replaced or deleted. The lock keeps each version for the same number of days even from the administrator's key. Use one number for both: if old versions were cleared sooner than the lock lasts, the lock would protect nothing more; if they were kept much longer, the bucket would hold that many days of every changed file (a server whose files change a lot uses roughly its daily change times the days, on top of the backup itself). Check your backups at least once in that time (Checking and restoring, below).

{{if rustfs}}
The quickest way is the app's **Terminal** (ServApps, this app, tab "Terminal"): RustFS ships its own client, `rc`, and the container already knows the administrator's key. The first lines give that key to `rc` through a file that is removed at once (never as a word on a command line), and the last line of the second block removes it again. Set the bucket's and the machine's names in the fields at the top of this guide first.

```sh id=admin-bucket runner=rustfs chain=admin
umask 077
printf '{"schema_version":1,"aliases":[{"name":"adm","endpoint":"http://127.0.0.1:9000","region":"us-east-1","signature":"v4","bucket_lookup":"auto","credentials":{"access_key":"%s","secret_key":"%s"}}]}' "$RUSTFS_ACCESS_KEY" "$RUSTFS_SECRET_KEY" > /tmp/adm.json
rc alias import /tmp/adm.json
rm -f /tmp/adm.json
rc bucket create --with-lock --ignore-existing adm/{{bucket}}
rc retention set governance 30d adm/{{bucket}} --default
rc bucket lifecycle rule add adm/{{bucket}} --noncurrent-expiry-days 30 --expired-object-delete-marker
rc bucket quota set adm/{{bucket}} 200G
```

What this did: a bucket with **Object Lock** (versioning comes with it); every version stays for **30 days** (`governance`: the administrator can still remove it, good while you test); a version that was replaced or deleted is removed 30 days later, so the bucket does not grow for ever; and the bucket may hold at most 200 GB (on a full disk the storage refuses even deletes). When you are sure, run the retention line again with `compliance` instead of `governance`: then nobody, not even you, can delete a version before its 30 days. Know what that costs: a machine that is broken into can fill the bucket's 200 GB with versions nobody can remove for 30 days, and its backups stop until they expire.

Then the key. Its policy lets it write, read and list its own bucket, read earlier versions, and delete only in the sense versioning gives: a delete adds a "deleted" marker and the earlier version stays. It cannot delete a version, change the lock or the rules, or touch another bucket. The secret is made by the terminal, not chosen.

```sh id=admin-key runner=rustfs chain=admin
umask 077
cat > /tmp/backup-{{name}}.json <<'EOF'
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:ListBucket", "s3:ListBucketVersions", "s3:GetBucketLocation", "s3:GetBucketVersioning", "s3:GetBucketObjectLockConfiguration", "s3:ListBucketMultipartUploads"],
      "Resource": ["arn:aws:s3:::{{bucket}}"]
    },
    {
      "Effect": "Allow",
      "Action": ["s3:PutObject", "s3:GetObject", "s3:GetObjectVersion", "s3:DeleteObject", "s3:AbortMultipartUpload", "s3:ListMultipartUploadParts", "s3:GetObjectRetention"],
      "Resource": ["arn:aws:s3:::{{bucket}}/*"]
    }
  ]
}
EOF
rc admin policy create adm backup-{{name}} /tmp/backup-{{name}}.json
rm -f /tmp/backup-{{name}}.json
secret=$(head -c 60 /dev/urandom | base64 | tr -dc 'A-Za-z0-9' | head -c 40)
rc admin user add adm {{name}}-backup "$secret"
rc admin policy attach adm backup-{{name}} --user {{name}}-backup
printf 'Access key: %s\nSecret key: %s\n' '{{name}}-backup' "$secret"
unset secret
rc alias remove adm
```

The two lines it prints are the key: put them in your password manager now; they are the `PASTE-ACCESS-KEY-HERE` and `PASTE-SECRET-KEY-HERE` of the examples. (`rc` takes the new secret as a word of its command, so for that instant it is visible to the server's process list; making the key in the console avoids even that.)

Which tools need delete: **restic** deletes its lock files at the end of every run and old data when you prune (allowed above: both only add markers); **rclone sync** deletes what you deleted on the machine (a marker too); `aws s3 cp`, the SDK examples and the WordPress plugins below only write. A machine that must not even read its own backups gets a policy with `s3:PutObject` alone (the SDKs and `aws s3 cp` work with it; restic, rclone and Kopia do not).

The same can be done in the console ({{console}}), with the names RustFS 1.0.5 gives them: sign in with the administrator's key ("Key Login"; Sign-in details on this app's page); **Buckets > Create Bucket** (switch on **Version** and **Object Lock**, and set the **Bucket Quota**); **Lifecycle** for the rule that clears old versions; **Policies** to create the policy above (paste the text); **Users** to create the key with its secret and that policy. The default retention is quickest with the `rc retention` line above. The console has no second factor: keep it at home.
{{end}}

{{if !rustfs}}
Make the bucket with versioning and Object Lock, a key limited to that bucket and, if your storage has them, a lifecycle rule that removes replaced versions after the days you chose and a quota, in the storage's own console ({{console}}) or with its command-line tool. The policy text of the RustFS steps is standard S3 and works on MinIO as well. Garage has neither versioning nor Object Lock: there a stolen key can delete for good, so keep a second copy elsewhere.
{{end}}

## Linux server or VPS {#linux}

### 1. The key and the settings, in one file only root can read

Make the file empty and private first, then open it in an editor (`nano /root/.s3-backup.env`) and paste the text below with your key: typed into an editor, the secret stays out of the shell's history.

```sh id=linux-env-file runner=linux chain=linux
install -m 600 /dev/null /root/.s3-backup.env
```

```sh id=linux-env runner=linux chain=linux file=/root/.s3-backup.env
AWS_ACCESS_KEY_ID=PASTE-ACCESS-KEY-HERE
```

{{end}}

### 2. restic: encrypted, incremental, deduplicated

Install it from your distribution (`apt install restic`, `dnf install restic`) or from its releases; the database examples need restic 0.17 or later (`restic version`). Then, once, create the repository, and make the first backup:

```sh id=linux-restic-init runner=linux chain=linux
set -a; . /root/.s3-backup.env; set +a
restic init
restic backup --host {{name}} --tag files /etc /var/www
```

A database goes in without a file on the disk: restic runs the dump itself and keeps nothing when the dump fails.

```sh id=linux-restic-db runner=linux chain=linux
set -a; . /root/.s3-backup.env; set +a
restic backup --host {{name}} --tag db --stdin-filename all-databases.sql --stdin-from-command -- \
  mariadb-dump --all-databases --single-transaction --routines --events --triggers
```

(With restic older than 0.17: `set -o pipefail; mariadb-dump … | restic backup --stdin --stdin-filename all-databases.sql`. The command then fails when the dump fails, but restic has already saved the cut-off dump as a snapshot: remove it with `restic forget <its id>`. Better to update restic.)

See what is there, and bring things back into a private folder, never over the live files first:

```sh id=linux-restic-restore runner=linux chain=linux
set -a; . /root/.s3-backup.env; set +a
restic snapshots
restore=$(mktemp -d /var/tmp/restore.XXXXXX)
restic restore latest --tag files --target "$restore"
diff -r /var/www "$restore/var/www"
echo "the files came back identical"
restic dump latest --tag db all-databases.sql > "$restore/all-databases.sql"
head -c 300 "$restore/all-databases.sql"; echo
restic check
rm -rf "$restore"
```

`mktemp -d` makes a folder only you can read; the last line removes the restored copy.

### 3. rclone: plain copies, one object per file

rclone keeps the files as they are (no encryption, no deduplication), so you can also open them in the console. The bucket's versions keep the old copies.

```sh id=linux-rclone runner=linux chain=linux
set -a; . /root/.s3-backup.env; set +a
rclone sync /var/www store:{{bucket}}/www
rclone ls store:{{bucket}}/www
restore=$(mktemp -d /var/tmp/restore.XXXXXX)
rclone copy store:{{bucket}}/www "$restore"
diff -r /var/www "$restore"
echo "the files came back identical"
rm -rf "$restore"
```

`NO_CHECK_BUCKET` in the settings is needed because the key may not create buckets. Older versions of a file: `rclone ls --s3-versions store:{{bucket}}/www`; the whole folder as it was at a moment: see "When something was overwritten or deleted" below.

### 4. Every night, by itself

A systemd timer (any recent distribution). The script and the units:

```sh id=linux-timer runner=linux chain=linux
install -m 700 /dev/null /usr/local/bin/s3-backup
cat > /usr/local/bin/s3-backup <<'EOF'
#!/bin/sh
set -eu
set -a; . /root/.s3-backup.env; set +a
restic backup --host {{name}} --tag files /etc /var/www
restic backup --host {{name}} --tag db --stdin-filename all-databases.sql --stdin-from-command -- \
  mariadb-dump --all-databases --single-transaction --routines --events --triggers
restic forget --host {{name}} --keep-daily 14 --keep-weekly 8 --keep-monthly 12
EOF
cat > /etc/systemd/system/s3-backup.service <<'EOF'
[Unit]
Description=Back up to the S3 storage
Wants=network-online.target
After=network-online.target

[Service]
Type=oneshot
ExecStart=/usr/local/bin/s3-backup
# root, because /etc and the databases are read; everything else is closed
Environment=RESTIC_CACHE_DIR=/var/cache/s3-backup
CacheDirectory=s3-backup
NoNewPrivileges=yes
PrivateTmp=yes
PrivateDevices=yes
ProtectSystem=strict
ProtectHome=read-only
ProtectKernelTunables=yes
ProtectKernelModules=yes
ProtectControlGroups=yes
RestrictSUIDSGID=yes
LockPersonality=yes
EOF
cat > /etc/systemd/system/s3-backup.timer <<'EOF'
[Unit]
Description=Back up to the S3 storage every night

[Timer]
OnCalendar=*-*-* 03:15:00
RandomizedDelaySec=30m
Persistent=true

[Install]
WantedBy=timers.target
EOF
/usr/local/bin/s3-backup
```

Then `systemctl daemon-reload && systemctl enable --now s3-backup.timer`; `systemctl list-timers s3-backup.timer` shows the next run and `journalctl -u s3-backup` what the last one said. The service runs as root because it reads `/etc` and the databases; the file system is read-only to it apart from restic's cache. A machine that backs up only a folder a user can read should run it as that user instead (`User=` in the service, and the settings files owned by that user). Without systemd, root's crontab does the same: `15 3 * * * /usr/local/bin/s3-backup`.

`restic forget` marks old snapshots; `restic prune` then deletes the data no snapshot needs any more. Run the prune once a month with the machine's own key, after `restic check`: with versioning its deletes only add markers, the space comes back when the bucket's rule clears those versions, and an earlier state can still be brought back until then.

```sh id=linux-prune runner=linux chain=linux
set -a; . /root/.s3-backup.env; set +a
restic check
restic prune
restic snapshots
```

## Website on shared hosting (PHP) {#website}

A website hosted elsewhere reaches only the internet address.{{if no_internet}} This app has none yet: see the top of the guide.{{end}}

### With a shell (SSH): rclone and restic

If the host gives you SSH, the Linux section works as it is: download the rclone or restic binary into your home folder (no root needed), keep the settings file in your home folder with mode 600, run the same commands with your site's folder, and let a cron job of the hosting panel replace the timer.

### Without a shell: a PHP script

Install the AWS SDK for PHP with Composer on your computer (`composer require aws/aws-sdk-php`) and upload, into a folder **above** the public web folder (for example `/home/you/backup/` when the site is `/home/you/public_html/`): the `vendor` folder, the script and its settings file. The script refuses to run if its working folder is inside the web folder, keeps everything it writes in that private folder (mode 700) and removes it whether the backup succeeds or fails. Run it from the hosting panel's cron jobs: `php /home/you/backup/backup.php`.

The settings, in `backup-config.php` (readable only by the site: `chmod 600 backup-config.php`):

```php id=php-config runner=php chain=php file=backup-config.php
<?php
return [
    'key'      => 'PASTE-ACCESS-KEY-HERE',
    'secret'   => 'PASTE-SECRET-KEY-HERE',
    'bucket'   => '{{bucket}}',
    'site'     => '/home/you/public_html',   // the folder to back up
    'web_root' => '/home/you/public_html',   // the public web folder: the script refuses to work inside it
    'db'       => ['host' => 'localhost', 'name' => 'site', 'user' => 'site', 'password' => 'PASTE-DATABASE-PASSWORD-HERE'],
    'dumper'   => 'auto',                    // 'auto': mysqldump when the host allows it, else PHP; 'php': always PHP
];
```

The script, `backup.php`:

```php id=php-backup runner=php chain=php file=backup.php
// mysqldump, run without a shell, its password in a private file (never on a command line)
function dumpWithMysqldump(array $db, string $out, string $work, array &$temporary): bool
{
    $disabled = array_map('trim', explode(',', (string) ini_get('disable_functions')));
    if (!function_exists('proc_open') || in_array('proc_open', $disabled, true)) {
        return false;
    }
    $binary = '';
    foreach (['/usr/bin/mysqldump', '/usr/bin/mariadb-dump', '/usr/local/bin/mysqldump'] as $candidate) {
        if (is_executable($candidate)) {
            $binary = $candidate;
            break;
        }
    }
    if ($binary === '') {
        return false;
    }
    $options = $work . '/my.cnf';
    $temporary[] = $options;
    file_put_contents($options, "[client]\nhost=\"{$db['host']}\"\nuser=\"{$db['user']}\"\npassword=\"" . addcslashes($db['password'], "\"\\") . "\"\n");
    chmod($options, 0600);
    $process = proc_open([$binary, '--defaults-extra-file=' . $options, '--single-transaction', '--routines', '--events', '--triggers',
        '--default-character-set=utf8mb4', '--result-file=' . $out, $db['name']], [1 => ['pipe', 'w'], 2 => ['pipe', 'w']], $pipes);
    if (!is_resource($process)) {
        return false;
    }
    stream_get_contents($pipes[1]);
    $errors = stream_get_contents($pipes[2]);
    $status = proc_close($process);
    unlink($options);
    if ($status !== 0) {
        fwrite(STDERR, "mysqldump failed ($status): " . trim($errors) . "; using the PHP dumper\n");
        return false;
    }
    return true;
}

// the PHP dumper: tables, rows (read one by one), views, triggers and routines
function dumpWithPhp(array $c, string $out): void
{
    $db = new PDO('mysql:host=' . $c['host'] . ';dbname=' . $c['name'] . ';charset=utf8mb4', $c['user'], $c['password'], [
        PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION,
        PDO::MYSQL_ATTR_USE_BUFFERED_QUERY => false,
    ]);
    $f = fopen($out, 'xb');
    $q = fn (string $name): string => '`' . str_replace('`', '``', $name) . '`';
    $noDefiner = fn (string $sql): string => preg_replace('/\sDEFINER=`[^`]*`@`[^`]*`/', '', $sql);
    $value = function ($v) use ($db): string {
        if ($v === null) {
            return 'NULL';
        }
        return mb_check_encoding((string) $v, 'UTF-8') ? $db->quote((string) $v) : '0x' . bin2hex((string) $v);
    };
    fwrite($f, "-- dump of {$c['name']} made by backup.php\nSET NAMES utf8mb4;\nSET FOREIGN_KEY_CHECKS=0;\nSET UNIQUE_CHECKS=0;\n\n");
    $list = fn (string $sql): array => $db->query($sql)->fetchAll(PDO::FETCH_NUM);
    $tables = array_column($list("SHOW FULL TABLES WHERE Table_type = 'BASE TABLE'"), 0);
    $views = array_column($list("SHOW FULL TABLES WHERE Table_type = 'VIEW'"), 0);
    foreach ($tables as $table) {
        $create = $list('SHOW CREATE TABLE ' . $q($table))[0][1];
        fwrite($f, 'DROP TABLE IF EXISTS ' . $q($table) . ";\n$create;\n");
        $rows = $db->query('SELECT * FROM ' . $q($table), PDO::FETCH_NUM);
        $batch = [];
        foreach ($rows as $row) {
            $batch[] = '(' . implode(',', array_map($value, $row)) . ')';
            if (count($batch) === 200) {
                fwrite($f, 'INSERT INTO ' . $q($table) . ' VALUES ' . implode(",\n", $batch) . ";\n");
                $batch = [];
            }
        }
        if ($batch) {
            fwrite($f, 'INSERT INTO ' . $q($table) . ' VALUES ' . implode(",\n", $batch) . ";\n");
        }
        $rows->closeCursor();
        fwrite($f, "\n");
    }
    foreach ($views as $view) {
        fwrite($f, 'DROP VIEW IF EXISTS ' . $q($view) . ";\n" . $noDefiner($list('SHOW CREATE VIEW ' . $q($view))[0][1]) . ";\n");
    }
    fwrite($f, "DELIMITER ;;\n");
    foreach (array_column($list('SHOW TRIGGERS'), 0) as $trigger) {
        fwrite($f, 'DROP TRIGGER IF EXISTS ' . $q($trigger) . ";;\n" . $noDefiner($list('SHOW CREATE TRIGGER ' . $q($trigger))[0][2]) . ";;\n");
    }
    foreach ($list('SELECT ROUTINE_NAME, ROUTINE_TYPE FROM information_schema.ROUTINES WHERE ROUTINE_SCHEMA = DATABASE()') as [$name, $type]) {
        fwrite($f, "DROP $type IF EXISTS " . $q($name) . ";;\n" . $noDefiner($list("SHOW CREATE $type " . $q($name))[0][2]) . ";;\n");
    }
    fwrite($f, "DELIMITER ;\nSET FOREIGN_KEY_CHECKS=1;\nSET UNIQUE_CHECKS=1;\n");
    fclose($f);
}

try {
    $stamp = date('Y-m-d-His');

    // 1. the files, as one zip
    $zipPath = "$work/site-$stamp.zip";
    $temporary[] = $zipPath;
    $zip = new ZipArchive();
    if ($zip->open($zipPath, ZipArchive::CREATE | ZipArchive::EXCL) !== true) {
        throw new RuntimeException("cannot create $zipPath");
    }
    $files = new RecursiveIteratorIterator(new RecursiveDirectoryIterator($config['site'], FilesystemIterator::SKIP_DOTS));
    foreach ($files as $file) {
        $zip->addFile($file->getPathname(), substr($file->getPathname(), strlen($config['site']) + 1));
    }
    $zip->close();
    upload($s3, $config['bucket'], $zipPath, "files/site-$stamp.zip");

    // 2. the database
    $sqlPath = "$work/db-$stamp.sql";
    $temporary[] = $sqlPath;
    if ($config['dumper'] === 'php' || !dumpWithMysqldump($config['db'], $sqlPath, $work, $temporary)) {
        if (is_file($sqlPath)) {
            unlink($sqlPath);
        }
        dumpWithPhp($config['db'], $sqlPath);
    }
    upload($s3, $config['bucket'], $sqlPath, "db/site-$stamp.sql");

    echo "backed up files/site-$stamp.zip and db/site-$stamp.sql\n";
} catch (Throwable $e) {
    fwrite(STDERR, 'backup failed: ' . $e->getMessage() . "\n");
    exit(1);
}
```

mysqldump is used when the host allows it (it is the complete dump). The PHP dumper is the fallback: it writes tables with their rows, then views, triggers and routines, with foreign-key checks off during the import; it does not dump events or other databases, and it leaves out the original owner (`DEFINER`) of views, triggers and routines, which then belong to the user who imports them.

To restore, download the newest pair (the script below, the console, or `aws s3 cp` from any machine), unzip the files over the site and import the SQL into an empty database (the hosting panel's phpMyAdmin, or `mysql newdb < db.sql`). Older pairs are in the bucket's versions. `list.php` lists them and downloads the newest database dump into the private folder:

## Databases {#databases}

restic runs the dump itself (`--stdin-from-command`, restic 0.17 or later): nothing is written to the local disk, the parts stay small, and a dump that fails leaves no snapshot and makes the command fail. The examples use the settings file of the Linux section, and restore into a private folder that is removed at the end.

### PostgreSQL

The connection comes from `~/.pgpass` (mode 600, or libpq ignores it) or the `PG…` variables. `pg_dump` saves one database without the roles that own it: the second backup line saves the roles, so that a new server can take the dump.

```sh id=db-pg runner=pg chain=pg
set -a; . /root/.s3-backup.env; set +a
restic snapshots >/dev/null 2>&1 || restic init
restic backup --host {{name}} --tag postgres --stdin-filename shop.dump --stdin-from-command -- pg_dump --format=custom shop
restic backup --host {{name}} --tag postgres-roles --stdin-filename roles.sql --stdin-from-command -- pg_dumpall --globals-only
restic snapshots --tag postgres
restore=$(mktemp -d /var/tmp/restore.XXXXXX)
restic dump latest --tag postgres shop.dump > "$restore/shop.dump"
createdb shop_restored
pg_restore --dbname=shop_restored "$restore/shop.dump"
psql -d shop_restored -c 'select count(*) from orders'
rm -rf "$restore"
```

On a new server, first `psql -f roles.sql` (from `restic dump latest --tag postgres-roles roles.sql`), then the database.

```python id=code-python runner=python chain=python file=s3_example.py
import os
import tempfile

import boto3
from boto3.s3.transfer import TransferConfig
from botocore.config import Config

# the key comes from AWS_ACCESS_KEY_ID and AWS_SECRET_ACCESS_KEY in the environment
s3 = boto3.client(
    "s3",
    endpoint_url="{{endpoint}}",
    region_name="{{region}}",
{{if ca}}
    verify="/etc/ssl/cosmos-ca.pem",
{{end}}
    config=Config(
        signature_version="s3v4",
        s3={"addressing_style": "path"},
        request_checksum_calculation="when_required",
        response_checksum_validation="when_required",
    ),
)
parts = TransferConfig(multipart_threshold=64 * 1024 * 1024, multipart_chunksize=64 * 1024 * 1024)

with tempfile.TemporaryDirectory() as work:
    report = os.path.join(work, "report.bin")
    with open(report, "wb") as f:

    s3.put_object(Bucket="{{bucket}}", Key="code/note.txt", Body=b"hello")

    s3.download_file("{{bucket}}", "code/report.bin", back, Config=parts)
```

### Node.js

```js id=code-node runner=node chain=node file=s3-example.mjs
import { S3Client, PutObjectCommand, GetObjectCommand, ListObjectsV2Command, DeleteObjectCommand } from '@aws-sdk/client-s3';
import { Upload } from '@aws-sdk/lib-storage';
import { getSignedUrl } from '@aws-sdk/s3-request-presigner';
import { createReadStream, mkdtempSync, rmSync, writeFileSync } from 'node:fs';
import { randomBytes } from 'node:crypto';
import { tmpdir } from 'node:os';
import { join } from 'node:path';

// the key comes from AWS_ACCESS_KEY_ID and AWS_SECRET_ACCESS_KEY in the environment
const s3 = new S3Client({
  endpoint: '{{endpoint}}',
  region: '{{region}}',
  forcePathStyle: true,
  requestChecksumCalculation: 'WHEN_REQUIRED',
  responseChecksumValidation: 'WHEN_REQUIRED',
});

const work = mkdtempSync(join(tmpdir(), 's3-'));
try {
  writeFileSync(join(work, 'big.bin'), randomBytes(150 * 1024 * 1024)); // 150 MB: sent in parts
  await new Upload({ client: s3, params: { Bucket: '{{bucket}}', Key: 'code/big.bin', Body: createReadStream(join(work, 'big.bin')) }, partSize: 64 * 1024 * 1024 }).done();
  await s3.send(new PutObjectCommand({ Bucket: '{{bucket}}', Key: 'code/node.txt', Body: 'hello' }));
  const list = await s3.send(new ListObjectsV2Command({ Bucket: '{{bucket}}', Prefix: 'code/' }));
  for (const item of list.Contents ?? []) console.log(item.Key, item.Size);
  const got = await s3.send(new GetObjectCommand({ Bucket: '{{bucket}}', Key: 'code/node.txt' }));
  if ((await got.Body.transformToString()) !== 'hello') throw new Error('the object came back different');
  console.log(await getSignedUrl(s3, new GetObjectCommand({ Bucket: '{{bucket}}', Key: 'code/node.txt' }), { expiresIn: 3600 }));
  await s3.send(new DeleteObjectCommand({ Bucket: '{{bucket}}', Key: 'code/node.txt' }));
} finally {
  rmSync(work, { recursive: true, force: true });
}
```

```go id=code-go runner=go chain=go file=main.go
package main

import (
	"bytes"
	"context"
	"crypto/rand"
	"fmt"
	"io"
	"log"

	"github.com/aws/aws-sdk-go-v2/aws"
	"github.com/aws/aws-sdk-go-v2/config"
	"github.com/aws/aws-sdk-go-v2/feature/s3/manager"
	"github.com/aws/aws-sdk-go-v2/service/s3"
)

func main() {
	ctx := context.Background()
	// the key comes from AWS_ACCESS_KEY_ID and AWS_SECRET_ACCESS_KEY in the environment
	cfg, err := config.LoadDefaultConfig(ctx,
		config.WithRegion("{{region}}"),
		config.WithRequestChecksumCalculation(aws.RequestChecksumCalculationWhenRequired),
		config.WithResponseChecksumValidation(aws.ResponseChecksumValidationWhenRequired),
	)
	if err != nil {
		log.Fatal(err)
	}
	client := s3.NewFromConfig(cfg, func(o *s3.Options) {
		o.BaseEndpoint = aws.String("{{endpoint}}")
		o.UsePathStyle = true
	})
	uploader := manager.NewUploader(client, func(u *manager.Uploader) { u.PartSize = 64 << 20 })
	big := make([]byte, 150<<20) // 150 MB: sent in parts
	if _, err := rand.Read(big); err != nil {
		log.Fatal(err)
	}
	if _, err := uploader.Upload(ctx, &s3.PutObjectInput{Bucket: aws.String("{{bucket}}"), Key: aws.String("code/go.bin"), Body: bytes.NewReader(big)}); err != nil {
		log.Fatal(err)
	}
	got, err := client.GetObject(ctx, &s3.GetObjectInput{Bucket: aws.String("{{bucket}}"), Key: aws.String("code/go.bin")})
	if err != nil {
		log.Fatal(err)
	}
	back, err := io.ReadAll(got.Body)
	if err != nil || !bytes.Equal(back, big) {
		log.Fatal("the object came back different")
	}
	list, err := client.ListObjectsV2(ctx, &s3.ListObjectsV2Input{Bucket: aws.String("{{bucket}}"), Prefix: aws.String("code/")})
	if err != nil {
		log.Fatal(err)
	}
	for _, item := range list.Contents {
		fmt.Println(*item.Key, *item.Size)
	}
	link, err := s3.NewPresignClient(client).PresignGetObject(ctx, &s3.GetObjectInput{Bucket: aws.String("{{bucket}}"), Key: aws.String("code/go.bin")})
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println(link.URL)
}
```

### curl, when there is nothing else

curl 8 and later signs S3 requests itself. It sends a whole file in one request{{if cloudflare}}, so here at most 100 MB{{end}}; use a tool above for bigger files. The key goes in a file only you can read, given with `-K` (`install -m 600 /dev/null ~/.s3-curl`, then an editor):

```text id=code-curl-config runner=curl chain=curl file=/root/.s3-curl
user = "PASTE-ACCESS-KEY-HERE:PASTE-SECRET-KEY-HERE"
aws-sigv4 = "aws:amz:{{region}}:s3"
fail
silent
show-error
```

```sh id=code-curl runner=curl chain=curl
chmod 600 /root/.s3-curl
{{if ca}}
export CURL_CA_BUNDLE=/etc/ssl/cosmos-ca.pem
{{end}}
work=$(mktemp -d)
echo "hello from curl" > "$work/note.txt"
curl -K /root/.s3-curl --upload-file "$work/note.txt" {{endpoint}}/{{bucket}}/code/curl.txt
curl -K /root/.s3-curl -o "$work/back.txt" {{endpoint}}/{{bucket}}/code/curl.txt
cmp "$work/note.txt" "$work/back.txt"
curl -K /root/.s3-curl "{{endpoint}}/{{bucket}}?list-type=2&prefix=code/" | head -c 400; echo
curl -K /root/.s3-curl -X DELETE {{endpoint}}/{{bucket}}/code/curl.txt
rm -rf "$work"
```

## Checking and restoring {#checking}

A backup is only a backup once something was brought back from it. At least once in the number of days the bucket keeps old versions (30 above), better monthly:

1. Look at what arrived: {{if admin}}in the console{{end}}{{if console}} ({{console}}){{end}}{{if !admin}}ask your administrator, or look{{end}} with `restic snapshots` and `rclone ls` as above. Every machine should have a backup of the last night.
2. Look at what changed lately (the block below lists every version, newest first): a burst of new versions you did not cause, or files missing from `rclone ls` that still have versions, is the sign of a machine that was broken into.
3. Restore one folder and one database into a private folder, as each section shows, and open a file or count a table.
4. Run `restic check` on each repository: it fails if the repository was damaged or overwritten.
5. Compare the bucket's size (the console's bucket page) with its quota.

```sh id=check-changes runner=linux chain=recover
set -a; . /root/.s3-backup.env; set +a
# every version of every file, newest first: earlier versions carry their date in the name
rclone lsf --s3-versions --recursive --format tp store:{{bucket}} | sort -r | head -20
```

Encryption: restic and Kopia encrypt with the repository password before anything leaves the machine; rclone and the plain copies do not (add `rclone crypt` if that matters). Keep the passwords and the keys in your password manager, not only on the machine they protect.

### When something was overwritten or deleted

First take the key away from whoever has it: {{if admin}}give the machine's key a new secret (the app's Terminal: the `rc alias import` lines of "Before the first backup", then `rc admin user passwd adm NAME-backup` with a new secret, then `rc alias remove adm`), {{end}}{{if !admin}}ask your administrator to give the machine's key a new secret, {{end}}and put the new secret in the settings file of a machine you trust. Then bring the bucket's content back as it was at a moment before the damage, into a new folder of the bucket, without touching what is there now: rclone reads the bucket as it was at that time (`version_at`, the key may read earlier versions) and writes the copy as new files. The time is in UTC.

```sh id=recover-restic runner=linux chain=recover
set -a; . /root/.s3-backup.env; set +a
WHEN='PASTE-TIME-BEFORE-DAMAGE-HERE'   # for example 2026-11-16T09:00:00Z
rclone copy "store,version_at='$WHEN':{{bucket}}/restic" store:{{bucket}}/restic-restored
export RESTIC_REPOSITORY=s3:{{endpoint}}/{{bucket}}/restic-restored
restic check
restic snapshots
restore=$(mktemp -d /var/tmp/restore.XXXXXX)
restic restore latest --tag files --target "$restore"
diff -r /var/www "$restore/var/www"
echo "the restic repository as it was before the damage works"
rm -rf "$restore"
```

From then on use `restic-restored` as the repository (change `RESTIC_REPOSITORY` in the settings file). The plain copies of rclone come back the same way, into a folder of the machine:

```sh id=recover-files runner=linux chain=recover
set -a; . /root/.s3-backup.env; set +a
WHEN='PASTE-TIME-BEFORE-DAMAGE-HERE'
restore=$(mktemp -d /var/tmp/restore.XXXXXX)
rclone copy "store,version_at='$WHEN':{{bucket}}/www" "$restore"
diff -r /var/www "$restore"
echo "the files are back as they were"
rm -rf "$restore"
```

This works for as long as the bucket keeps the earlier versions (30 days after they were replaced or deleted, above). What protects them: the key cannot delete a version or change the bucket's rules; Object Lock also stops the administrator's key for those days. What does not: someone with the administrator's key and more than those days, or with a shell on this server (the files are on its disk), or this server's disk dying. Keep a second copy of what matters elsewhere.

## Limits and problems {#trouble}

{{show limits}}

Cosmos can limit a URL (its shield, a number of requests per minute, a bandwidth, a timeout, blocking of bots and of uploads without a Referer): backup tools send many requests and some last long, so the storage's addresses for backups should have none of these. A URL without a timeout never cuts a request; if a timeout is set, give it 24 hours. Cloudflare's 100 MB per request is Cloudflare's own limit, not Cosmos'.

| You see | Why, and what to do |
| --- | --- |
| `SignatureDoesNotMatch` | the secret is wrong, the region is not `{{region}}`, or the machine's clock is off |
| `RequestTimeTooSkewed` | the machine's clock is more than 15 minutes off: switch on automatic time |
| HTTP 413, "Request Entity Too Large" | a request over 100 MB through the internet address: set your tool's part size (the 64M settings above) |
| `x509: certificate signed by unknown authority`, `CERTIFICATE_VERIFY_FAILED`, `unable to get local issuer certificate` | the home address with a tool that was not given Cosmos' certificate file (see Connection settings) |
| `AccessDenied` | the key may not do that: another bucket, deleting a version, creating a bucket (rclone: `no_check_bucket`) |
| `NoSuchBucket` or a name error | the bucket's name, or a client that puts the bucket in front of the address: switch path style on |
| `Could not resolve host` with a `.local` address | this machine does not resolve `.local` names (a VPN, some Android and Windows set-ups): use the internet address, or add the name to the machine's hosts file |
| errors about checksums or `x-amz-checksum` | a 2025 or later SDK: the `when_required` settings above |
| restic: "repository is already locked" | a run was cut off: `restic unlock`, then `restic check` |
| restic: `unknown flag: --stdin-from-command` | restic older than 0.17: update it |
| HTTP 429 "Too many requests" | Cosmos' shield or its limit per minute on that address (see above) |
| HTTP 502 or 504 after the same number of seconds every time, on a long upload or download | the URL's timeout in Cosmos (it cuts a request that lasts longer): set it to 24 hours, or none |
| HTTP 400 "Bad Request: Invalid request" on uploads and deletes | the URL blocks requests without a Referer ("API abuse"): switch that off for the storage's addresses |
| "Bucket quota exceeded" | the bucket is full: raise its quota, or let the lifecycle rule clear old versions |
