This app is an object storage that speaks the S3 protocol, the language almost every backup tool understands. A backup tool sends files to a **bucket** (a top-level folder), signs every request with a **key** (an access key and its secret, like a user name and a password), and talks to an **endpoint** (the address below) in a **region** (here `{{region}}`, a name the signature needs, nothing to do with geography). Use **path-style addressing**: the bucket goes after the address (`{{endpoint}}/bucket`), never in front of it as `bucket.host`. Give every machine or site its own bucket and its own key that can reach only that bucket; with versioning and a lock on the bucket, even a site that is broken into cannot erase its own history. Every example below already holds this server's address for the place chosen above; the parts you replace are marked like `PASTE-SECRET-KEY-HERE`.

{{if no_internet}}
> **Warning:** this app has no internet address. A website hosted elsewhere, a phone away from home or a server in a data centre cannot reach it. Give it one (its page in ServApps, "Internet…"), or back such machines up through a machine at home.
{{end}}

## Before the first backup {#before admin}

Do this once per thing you back up (a server, a website, a phone). You need: a bucket, a key that can reach only that bucket, a lock so that old versions cannot be deleted, a rule that clears old versions so the disk does not fill, and a size limit. Never give the administrator's key to a machine or a website.

{{if rustfs}}
The quickest way is the app's **Terminal** (ServApps, this app, tab "Terminal"): RustFS ships its own client, `rc`, and the container already knows the administrator's key, so no secret is typed or shown. Set the bucket's and the machine's names in the fields at the top of this guide first.

```sh id=admin-bucket runner=rustfs chain=admin
rc alias set adm http://127.0.0.1:9000 "$RUSTFS_ACCESS_KEY" "$RUSTFS_SECRET_KEY"
rc bucket create --with-lock --ignore-existing adm/{{bucket}}
rc retention set governance 30d adm/{{bucket}} --default
rc bucket lifecycle rule add adm/{{bucket}} --noncurrent-expiry-days 30 --expired-object-delete-marker
rc bucket quota set adm/{{bucket}} 200G
```

What this did: a bucket with **Object Lock** (versioning comes with it); every version written stays undeletable for **30 days** (`governance`: the administrator can still remove it, good while you test; when you are sure, run the same line with `compliance`: then nobody, not even you, can delete a version before its time, and the disk space stays used that long); a version that was replaced or deleted is removed 30 days later, so the bucket does not grow for ever; and the bucket may hold at most 200 GB (on a full disk the storage refuses even deletes).

Then the key. Its policy lets it write, read and list its own bucket, and delete only in the sense versioning gives: a delete adds a "deleted" marker, the old version stays. It cannot delete a version, change the lock or touch another bucket. Choose the secret yourself: letters and digits, at least 20 of them.

```sh id=admin-key runner=rustfs chain=admin
cat > /tmp/backup-{{name}}.json <<'EOF'
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:ListBucket", "s3:ListBucketVersions", "s3:GetBucketLocation", "s3:GetBucketVersioning", "s3:GetBucketObjectLockConfiguration", "s3:ListBucketMultipartUploads"],
      "Resource": ["arn:aws:s3:::{{bucket}}"]
    },
    {
      "Effect": "Allow",
      "Action": ["s3:PutObject", "s3:GetObject", "s3:GetObjectVersion", "s3:DeleteObject", "s3:AbortMultipartUpload", "s3:ListMultipartUploadParts", "s3:GetObjectRetention"],
      "Resource": ["arn:aws:s3:::{{bucket}}/*"]
    }
  ]
}
EOF
rc admin policy create adm backup-{{name}} /tmp/backup-{{name}}.json
rc admin user add adm {{name}}-backup 'CHOOSE-A-SECRET-KEY-HERE'
rc admin policy attach adm backup-{{name}} --user {{name}}-backup
rm /tmp/backup-{{name}}.json
```

The key's access key is `{{name}}-backup` and its secret is what you chose: these are the `PASTE-ACCESS-KEY-HERE` and `PASTE-SECRET-KEY-HERE` of the examples. Write them in your password manager now.

Which tools need delete: **restic** deletes its lock files at the end of every run (allowed above: it only adds a marker); **rclone sync** deletes what you deleted on the machine (a marker too: the file stays in the bucket's history); `aws s3 cp`, the SDK examples and the WordPress plugins below only write. A machine that must not even read its own backups gets a policy with `s3:PutObject` alone (the SDKs and `aws s3 cp` work with it; restic, rclone and Kopia do not).

The same can be done in the console ({{console}}), with the names RustFS 1.0.5 gives them: sign in with the administrator's key ("Key Login"; Sign-in details on this app's page); **Buckets > Create Bucket** (switch on **Version** and **Object Lock**, and set the **Bucket Quota**); **Lifecycle** for the rule that clears old versions; **Policies** to create the policy above (paste the text); **Users** to create the key with its secret and that policy. The default retention of 30 days is quickest with the `rc retention` line above. The console has no second factor: keep it at home.
{{end}}

{{if !rustfs}}
Make the bucket with versioning and Object Lock, a key limited to that bucket and, if your storage has them, a lifecycle rule for old versions and a quota, in the storage's own console ({{console}}) or with its command-line tool. The policy text of the RustFS steps is standard S3 and works on MinIO as well. Garage has neither versioning nor Object Lock: its keys are made with `garage key create` and given a bucket with `garage bucket allow`.
{{end}}

## Linux server or VPS {#linux}

### 1. The key and the settings, in one file only root can read

```sh id=linux-env runner=linux chain=linux
cat > /root/.s3-backup.env <<'EOF'
AWS_ACCESS_KEY_ID=PASTE-ACCESS-KEY-HERE
AWS_SECRET_ACCESS_KEY=PASTE-SECRET-KEY-HERE
AWS_DEFAULT_REGION={{region}}
AWS_ENDPOINT_URL={{endpoint}}
RESTIC_REPOSITORY=s3:{{endpoint}}/{{bucket}}/restic
RESTIC_PASSWORD_FILE=/root/.restic-password
{{if ca}}
AWS_CA_BUNDLE=/etc/ssl/cosmos-ca.pem
RESTIC_CACERT=/etc/ssl/cosmos-ca.pem
RCLONE_CA_CERT=/etc/ssl/cosmos-ca.pem
{{end}}
EOF
echo 'CHOOSE-A-REPOSITORY-PASSWORD-HERE' > /root/.restic-password
chmod 600 /root/.s3-backup.env /root/.restic-password
```

The repository password encrypts the backups: without it they cannot be read, by anyone. Keep a copy somewhere else than this machine (your password manager).

### 2. restic: encrypted, incremental, deduplicated

Install it from your distribution (`apt install restic`, `dnf install restic`) or from its releases. Then, once, create the repository, and make the first backup:

```sh id=linux-restic-init runner=linux chain=linux
set -a; . /root/.s3-backup.env; set +a
restic init
restic backup --host {{name}} --tag files /etc /var/www
```

A database goes in without a file on the disk (the dump is streamed):

```sh id=linux-restic-db runner=linux chain=linux
set -a; . /root/.s3-backup.env; set +a
mariadb-dump --all-databases --single-transaction | restic backup --host {{name}} --tag db --stdin --stdin-filename all-databases.sql
```

See what is there, and bring things back (into another folder, never over the live one first):

```sh id=linux-restic-restore runner=linux chain=linux
set -a; . /root/.s3-backup.env; set +a
restic snapshots
restic restore latest --tag files --target /tmp/restore
diff -r /var/www /tmp/restore/var/www && echo "the files came back identical"
restic dump latest --tag db all-databases.sql > /tmp/all-databases.sql
head -c 300 /tmp/all-databases.sql; echo
restic check
```

### 3. rclone: plain copies, one object per file

rclone keeps the files as they are (no encryption, no deduplication), so you can also open them in the console. The bucket's versioning keeps the old copies.

```sh id=linux-rclone runner=linux chain=linux
set -a; . /root/.s3-backup.env; set +a
export RCLONE_CONFIG_STORE_TYPE=s3 RCLONE_CONFIG_STORE_PROVIDER=Other RCLONE_CONFIG_STORE_ENV_AUTH=true \
  RCLONE_CONFIG_STORE_ENDPOINT={{endpoint}} RCLONE_CONFIG_STORE_REGION={{region}} \
  RCLONE_CONFIG_STORE_FORCE_PATH_STYLE=true RCLONE_CONFIG_STORE_NO_CHECK_BUCKET=true
{{if cloudflare}}
export RCLONE_CONFIG_STORE_UPLOAD_CUTOFF=64M RCLONE_CONFIG_STORE_CHUNK_SIZE=64M
{{end}}
rclone sync /var/www store:{{bucket}}/www
rclone ls store:{{bucket}}/www
rclone copy store:{{bucket}}/www /tmp/restore-www
diff -r /var/www /tmp/restore-www && echo "the files came back identical"
```

{{if cloudflare}}
The two `64M` settings matter here: rclone sends a file of up to 200 MB in one request by default, and the 100 MB limit of the internet path refuses it.
{{end}}

`NO_CHECK_BUCKET` is needed because the key may not create buckets. Older versions of a file: `rclone ls --s3-versions store:{{bucket}}/www`; the whole folder as it was at a moment: `rclone copy --s3-version-at "2026-11-01 12:00" store:{{bucket}}/www /tmp/then`.

### 4. Every night, by itself

A systemd timer (any recent distribution). Put the backup commands in a script, and the timer next to it:

```sh id=linux-timer runner=linux chain=linux
cat > /usr/local/bin/s3-backup <<'EOF'
#!/bin/sh
set -eu
set -a; . /root/.s3-backup.env; set +a
restic backup --host {{name}} --tag files /etc /var/www
restic forget --host {{name}} --keep-daily 14 --keep-weekly 8 --keep-monthly 12
EOF
chmod 700 /usr/local/bin/s3-backup
cat > /etc/systemd/system/s3-backup.service <<'EOF'
[Unit]
Description=Back up to the S3 storage
Wants=network-online.target
After=network-online.target

[Service]
Type=oneshot
ExecStart=/usr/local/bin/s3-backup
EOF
cat > /etc/systemd/system/s3-backup.timer <<'EOF'
[Unit]
Description=Back up to the S3 storage every night

[Timer]
OnCalendar=*-*-* 03:15:00
RandomizedDelaySec=30m
Persistent=true

[Install]
WantedBy=timers.target
EOF
/usr/local/bin/s3-backup
```

Then `systemctl daemon-reload && systemctl enable --now s3-backup.timer`; `systemctl list-timers s3-backup.timer` shows the next run and `journalctl -u s3-backup` what the last one said. Without systemd, a line in root's crontab does the same: `15 3 * * * /usr/local/bin/s3-backup`.

> **Note:** `restic forget` only marks old snapshots as forgotten; the space comes back when `restic prune` runs, which needs to delete data. With the locked bucket and the key above, run the prune on a trusted machine with the administrator's key, never from the machine being backed up.

## Website on shared hosting (PHP) {#website}

A website hosted elsewhere reaches only the internet address.{{if no_internet}} This app has none yet: see the top of the guide.{{end}}

### With a shell (SSH): rclone

If the host gives you SSH, the Linux section works as it is: download the rclone binary into your home folder (no root needed), run the same commands with your site's folder, and let a cron job of the hosting panel replace the timer.

### Without a shell: a PHP script

Install the AWS SDK for PHP with Composer on your computer (`composer require aws/aws-sdk-php`), upload the `vendor` folder next to the script, outside the public web folder, and run the script from the hosting panel's cron jobs. The script holds the keys: keep it outside the web folder, readable only by the site.

```php id=php-backup runner=php chain=php file=backup.php
<?php
// Backs up the site's folder and its database to the S3 storage.
require __DIR__ . '/vendor/autoload.php';

$config = [
    'key'    => 'PASTE-ACCESS-KEY-HERE',
    'secret' => 'PASTE-SECRET-KEY-HERE',
    'bucket' => '{{bucket}}',
    'site'   => getenv('SITE_DIR') ?: '/var/www/site',
    'db'     => ['host' => getenv('DB_HOST') ?: 'localhost', 'name' => 'site', 'user' => 'site', 'password' => 'PASTE-DATABASE-PASSWORD-HERE'],
];

$s3 = new Aws\S3\S3Client([
    'version' => 'latest',
    'region' => '{{region}}',
    'endpoint' => '{{endpoint}}',
    'use_path_style_endpoint' => true,
    'credentials' => ['key' => $config['key'], 'secret' => $config['secret']],
    'request_checksum_calculation' => 'when_required',
    'response_checksum_validation' => 'when_required',
{{if ca}}
    'http' => ['verify' => '/etc/ssl/cosmos-ca.pem'],
{{end}}
]);

$stamp = date('Y-m-d-His');

// 1. the files, as one zip
$zipPath = sys_get_temp_dir() . "/site-$stamp.zip";
$zip = new ZipArchive();
$zip->open($zipPath, ZipArchive::CREATE);
$files = new RecursiveIteratorIterator(new RecursiveDirectoryIterator($config['site'], FilesystemIterator::SKIP_DOTS));
foreach ($files as $file) {
    $zip->addFile($file->getPathname(), substr($file->getPathname(), strlen($config['site']) + 1));
}
$zip->close();
(new Aws\S3\MultipartUploader($s3, $zipPath, [
    'bucket' => $config['bucket'],
    'key' => "files/site-$stamp.zip",
    'part_size' => 64 * 1024 * 1024,
]))->upload();
unlink($zipPath);

// 2. the database, as SQL, row by row into a temporary file
$db = new PDO('mysql:host=' . $config['db']['host'] . ';dbname=' . $config['db']['name'], $config['db']['user'], $config['db']['password']);
$sqlPath = sys_get_temp_dir() . "/db-$stamp.sql";
$out = fopen($sqlPath, 'w');
foreach ($db->query('SHOW TABLES')->fetchAll(PDO::FETCH_COLUMN) as $table) {
    fwrite($out, $db->query("SHOW CREATE TABLE `$table`")->fetch(PDO::FETCH_NUM)[1] . ";\n");
    foreach ($db->query("SELECT * FROM `$table`", PDO::FETCH_NUM) as $row) {
        $values = array_map(fn ($v) => $v === null ? 'NULL' : $db->quote($v), $row);
        fwrite($out, "INSERT INTO `$table` VALUES (" . implode(',', $values) . ");\n");
    }
}
fclose($out);
(new Aws\S3\MultipartUploader($s3, $sqlPath, [
    'bucket' => $config['bucket'],
    'key' => "db/site-$stamp.sql",
    'part_size' => 64 * 1024 * 1024,
]))->upload();
unlink($sqlPath);

echo "backed up files/site-$stamp.zip and db/site-$stamp.sql\n";
```

```sh id=php-run runner=php chain=php
php backup.php
```

To restore, download the newest pair (the console, or `aws s3 cp` from any machine), unzip the files over the site and import the SQL in the hosting panel's phpMyAdmin. Older ones are in the bucket's versions:

```php id=php-list runner=php chain=php file=list.php
<?php
require __DIR__ . '/vendor/autoload.php';
$s3 = new Aws\S3\S3Client([
    'version' => 'latest', 'region' => '{{region}}', 'endpoint' => '{{endpoint}}', 'use_path_style_endpoint' => true,
    'credentials' => ['key' => 'PASTE-ACCESS-KEY-HERE', 'secret' => 'PASTE-SECRET-KEY-HERE'],
    'request_checksum_calculation' => 'when_required', 'response_checksum_validation' => 'when_required',
{{if ca}}
    'http' => ['verify' => '/etc/ssl/cosmos-ca.pem'],
{{end}}
]);
foreach ($s3->listObjectVersions(['Bucket' => '{{bucket}}', 'Prefix' => 'files/'])['Versions'] ?? [] as $v) {
    echo $v['Key'], '  ', $v['Size'], ' bytes  ', $v['LastModified'], '  version ', $v['VersionId'], "\n";
}
$s3->getObject(['Bucket' => '{{bucket}}', 'Key' => $v['Key'], 'VersionId' => $v['VersionId'], 'SaveAs' => sys_get_temp_dir() . '/restored.zip']);
echo 'restored ', filesize(sys_get_temp_dir() . '/restored.zip'), " bytes\n";
```

```sh id=php-list-run runner=php chain=php

```

### WordPress

Two free plugins take a custom S3 address with path style (read in their code on 2026-11-17; their screens were not run by Cosmos' tests):

- **UpdraftPlus** (free): Settings > Remote Storage > "S3-Compatible (Generic)". **S3 access key**: `PASTE-ACCESS-KEY-HERE`, **S3 secret key**: `PASTE-SECRET-KEY-HERE`, **S3 location**: `{{bucket}}/wordpress`, **S3 end-point**: `{{endpoint_host}}` (without `https://`), **Bucket access style**: Path style. It has no region field and sends 5 MB parts.
- **BackWPup** (free): a job's destination "S3 Service", the custom service: **Endpoint** `{{endpoint}}`, **Region** `{{region}}`, tick **Destination provides only Pathstyle buckets** and **Destination supports multipart**, then the keys and the bucket `{{bucket}}`.

WPvivid's free S3-compatible form takes its region from the address and does not fit, XCloner has no path style, All-in-One WP Migration and Duplicator need their paid versions for this.

Other CMS: Joomla's Akeeba Backup sends to S3 in its paid edition only; Drupal, PrestaShop and Magento have no maintained free module for it: use the PHP script above or rclone. Nextcloud's "External storage" can mount a bucket, but that is file access, not a backup.

## Databases {#databases}

The dump is streamed straight into the storage: nothing is written to the local disk, and the parts stay small. The examples use restic and the settings file of the Linux section; with rclone, replace `restic backup --stdin …` by `rclone rcat store:{{bucket}}/db/NAME.sql`.

### PostgreSQL

```sh id=db-pg runner=pg chain=pg
set -a; . /root/.s3-backup.env; set +a
restic snapshots >/dev/null 2>&1 || restic init
pg_dump --format=custom shop | restic backup --host {{name}} --tag postgres --stdin --stdin-filename shop.dump
restic snapshots --tag postgres
restic dump latest --tag postgres shop.dump > /tmp/shop.dump
createdb shop_restored
pg_restore --dbname=shop_restored /tmp/shop.dump
psql -d shop_restored -c 'select count(*) from orders'
```

(`PGHOST`, `PGUSER` and `PGPASSWORD`, or a `~/.pgpass` file, tell `pg_dump` where the database is.)

### MariaDB or MySQL

```sh id=db-maria runner=maria chain=maria
set -a; . /root/.s3-backup.env; set +a
restic snapshots >/dev/null 2>&1 || restic init
mariadb-dump --single-transaction --routines shop | restic backup --host {{name}} --tag mariadb --stdin --stdin-filename shop.sql
restic dump latest --tag mariadb shop.sql > /tmp/shop.sql
mariadb -e 'create database shop_restored'
mariadb shop_restored < /tmp/shop.sql
mariadb -N -e 'select count(*) from shop_restored.orders'
```

(On MySQL the commands are `mysqldump` and `mysql`. The user and password go in `~/.my.cnf`.)

### MongoDB

```sh id=db-mongo runner=mongo chain=mongo
set -a; . /root/.s3-backup.env; set +a
restic snapshots >/dev/null 2>&1 || restic init
mongodump --uri "$MONGO_URI" --archive --gzip | restic backup --host {{name}} --tag mongo --stdin --stdin-filename mongo.archive.gz
restic dump latest --tag mongo mongo.archive.gz | mongorestore --uri "$MONGO_URI" --archive --gzip --nsFrom 'shop.*' --nsTo 'shop_restored.*'
mongosh "$MONGO_URI" --quiet --eval 'db.getSiblingDB("shop_restored").orders.countDocuments()'
```

(`MONGO_URI` is the database's address with its user, `mongodb://user:password@host:27017/?authSource=admin`; keep it in the settings file.)

## Docker apps and volumes {#docker}

**On this server**, Cosmos backs up its own apps' volumes itself: Configuration > Backups (snapshots of folders and volumes). Use this storage for the other machines.

**On another server**, run restic in a container next to the apps, with their volumes mounted read-only. With `docker compose`:

```yaml id=docker-compose runner=docker chain=docker file=compose.yaml
services:
  backup:
    image: restic/restic:0.19.1
    entrypoint: ["/bin/sh", "-c"]
    command: ["restic snapshots >/dev/null 2>&1 || restic init; restic backup --host {{name}} --tag volumes /data"]
    environment:
      AWS_ACCESS_KEY_ID: PASTE-ACCESS-KEY-HERE
      AWS_SECRET_ACCESS_KEY: PASTE-SECRET-KEY-HERE
      AWS_DEFAULT_REGION: {{region}}
      RESTIC_REPOSITORY: s3:{{endpoint}}/{{bucket}}/docker
      RESTIC_PASSWORD: CHOOSE-A-REPOSITORY-PASSWORD-HERE
{{if ca}}
      RESTIC_CACERT: /ca/cosmos-ca.pem
{{end}}
    volumes:
      - app-data:/data/app-data:ro
{{if ca}}
      - ./cosmos-ca.pem:/ca/cosmos-ca.pem:ro
{{end}}
{{if container}}
    networks: [storage]
{{end}}
volumes:
  app-data:
    external: true
{{if container}}
networks:
  storage:
    name: {{network}}
    external: true
{{end}}
```

```sh id=docker-run runner=docker chain=docker
docker compose run --rm backup
docker compose run --rm backup "restic snapshots --tag volumes"
```

`app-data` stands for the volume of your app (`docker volume ls`). Schedule `docker compose run --rm backup` with the machine's timer or cron, as in the Linux section. A database inside a container is dumped with `docker exec`: `docker exec db pg_dump -U app app | restic backup --stdin …`.

## Windows {#windows}

### restic with Task Scheduler

Download `restic_*_windows_amd64.zip` from restic's releases, put `restic.exe` in a folder of your `PATH`, and keep the settings in a script only you can read. In PowerShell:

```powershell id=win-restic runner=pwsh chain=pwsh file=backup.ps1
$env:AWS_ACCESS_KEY_ID = 'PASTE-ACCESS-KEY-HERE'
$env:AWS_SECRET_ACCESS_KEY = 'PASTE-SECRET-KEY-HERE'
$env:AWS_DEFAULT_REGION = '{{region}}'
$env:RESTIC_REPOSITORY = 's3:{{endpoint}}/{{bucket}}/windows'
$env:RESTIC_PASSWORD = 'CHOOSE-A-REPOSITORY-PASSWORD-HERE'
{{if ca}}
$env:RESTIC_CACERT = Join-Path $HOME 'cosmos-ca.pem'
{{end}}
$folders = @(Join-Path $HOME 'Documents')
restic snapshots *> $null
if ($LASTEXITCODE -ne 0) { restic init; if ($LASTEXITCODE -ne 0) { exit 1 } }
restic backup --host {{name}} --tag documents @folders
if ($LASTEXITCODE -ne 0) { exit 1 }
restic snapshots --tag documents
```

```powershell id=win-run runner=pwsh chain=pwsh
pwsh -File ./backup.ps1
```

Run it every day at 13:00, as yourself:

```powershell id=win-schedule
$action = New-ScheduledTaskAction -Execute 'pwsh.exe' -Argument "-NoProfile -File `"$HOME\backup.ps1`""
$trigger = New-ScheduledTaskTrigger -Daily -At 13:00
Register-ScheduledTask -TaskName 'S3 backup' -Action $action -Trigger $trigger -Description 'Back up to the S3 storage'
```

(`powershell.exe` instead of `pwsh.exe` on a Windows without PowerShell 7.) To restore: `restic restore latest --target C:\restore`. rclone works as on Linux (`rclone.exe`, the same variables set with `$env:`).

## From code, any language {#code}

Every recent AWS SDK sends checksum headers that some S3-compatible servers do not accept; the examples switch them to "when required", which every S3 server accepts. The environment variables `AWS_REQUEST_CHECKSUM_CALCULATION=when_required` and `AWS_RESPONSE_CHECKSUM_VALIDATION=when_required` do the same for any AWS SDK and the AWS CLI.

### AWS CLI

```sh id=code-aws runner=aws chain=aws
export AWS_ACCESS_KEY_ID='PASTE-ACCESS-KEY-HERE' AWS_SECRET_ACCESS_KEY='PASTE-SECRET-KEY-HERE'
export AWS_DEFAULT_REGION={{region}} AWS_ENDPOINT_URL={{endpoint}}
export AWS_REQUEST_CHECKSUM_CALCULATION=when_required AWS_RESPONSE_CHECKSUM_VALIDATION=when_required
{{if ca}}
export AWS_CA_BUNDLE=/etc/ssl/cosmos-ca.pem
{{end}}
aws configure set default.s3.addressing_style path
echo "hello" > hello.txt
aws s3 cp hello.txt s3://{{bucket}}/code/hello.txt
aws s3 ls s3://{{bucket}}/code/
aws s3 cp s3://{{bucket}}/code/hello.txt hello-back.txt && cat hello-back.txt
aws s3api list-object-versions --bucket {{bucket}} --prefix code/hello.txt --query 'Versions[].[VersionId,LastModified]' --output text
aws s3 presign s3://{{bucket}}/code/hello.txt --expires-in 3600
aws s3 rm s3://{{bucket}}/code/hello.txt
```

`aws s3 cp` sends anything over 8 MB in parts of 8 MB. With a locked bucket `rm` only hides the file: `list-object-versions` still shows it.

```python id=code-python runner=python chain=python file=s3_example.py

from boto3.s3.transfer import TransferConfig
from botocore.config import Config

s3 = boto3.client(
    "s3",
    endpoint_url="{{endpoint}}",
    region_name="{{region}}",

{{end}}

        s3={"addressing_style": "path"},

    ),
)
parts = TransferConfig(multipart_threshold=64 * 1024 * 1024, multipart_chunksize=64 * 1024 * 1024)

with open("report.bin", "wb") as f:
    f.write(b"x" * (150 * 1024 * 1024))  # 150 MB: sent in parts
s3.upload_file("report.bin", "{{bucket}}", "code/report.bin", Config=parts)
s3.put_object(Bucket="{{bucket}}", Key="code/note.txt", Body=b"hello")

    print(item["Key"], item["Size"])
```

```js id=code-node runner=node chain=node file=s3-example.mjs
import { S3Client, PutObjectCommand, GetObjectCommand, ListObjectsV2Command, DeleteObjectCommand } from '@aws-sdk/client-s3';
import { Upload } from '@aws-sdk/lib-storage';
import { getSignedUrl } from '@aws-sdk/s3-request-presigner';
import { createReadStream, writeFileSync } from 'node:fs';

const s3 = new S3Client({
  endpoint: '{{endpoint}}',
  region: '{{region}}',
  forcePathStyle: true,
  credentials: { accessKeyId: 'PASTE-ACCESS-KEY-HERE', secretAccessKey: 'PASTE-SECRET-KEY-HERE' },
  requestChecksumCalculation: 'WHEN_REQUIRED',
  responseChecksumValidation: 'WHEN_REQUIRED',
});

writeFileSync('big.bin', Buffer.alloc(150 * 1024 * 1024, 120)); // 150 MB: sent in parts
await new Upload({ client: s3, params: { Bucket: '{{bucket}}', Key: 'code/big.bin', Body: createReadStream('big.bin') }, partSize: 64 * 1024 * 1024 }).done();
await s3.send(new PutObjectCommand({ Bucket: '{{bucket}}', Key: 'code/node.txt', Body: 'hello' }));
const list = await s3.send(new ListObjectsV2Command({ Bucket: '{{bucket}}', Prefix: 'code/' }));
for (const item of list.Contents ?? []) console.log(item.Key, item.Size);
const got = await s3.send(new GetObjectCommand({ Bucket: '{{bucket}}', Key: 'code/node.txt' }));
console.log(await got.Body.transformToString());
console.log(await getSignedUrl(s3, new GetObjectCommand({ Bucket: '{{bucket}}', Key: 'code/node.txt' }), { expiresIn: 3600 }));
await s3.send(new DeleteObjectCommand({ Bucket: '{{bucket}}', Key: 'code/node.txt' }));
```

### Go

```go id=code-go runner=go chain=go file=main.go
package main

import (
	"bytes"
	"context"
	"fmt"
	"io"
	"log"

	"github.com/aws/aws-sdk-go-v2/aws"
	"github.com/aws/aws-sdk-go-v2/config"
	"github.com/aws/aws-sdk-go-v2/credentials"
	"github.com/aws/aws-sdk-go-v2/feature/s3/manager"
	"github.com/aws/aws-sdk-go-v2/service/s3"
)

func main() {
	ctx := context.Background()
	cfg, err := config.LoadDefaultConfig(ctx,
		config.WithRegion("{{region}}"),
		config.WithCredentialsProvider(credentials.NewStaticCredentialsProvider("PASTE-ACCESS-KEY-HERE", "PASTE-SECRET-KEY-HERE", "")),
		config.WithRequestChecksumCalculation(aws.RequestChecksumCalculationWhenRequired),
		config.WithResponseChecksumValidation(aws.ResponseChecksumValidationWhenRequired),
	)
	if err != nil {
		log.Fatal(err)
	}
	client := s3.NewFromConfig(cfg, func(o *s3.Options) {
		o.BaseEndpoint = aws.String("{{endpoint}}")
		o.UsePathStyle = true
	})
	uploader := manager.NewUploader(client, func(u *manager.Uploader) { u.PartSize = 64 << 20 })
	big := bytes.Repeat([]byte("x"), 150<<20) // 150 MB: sent in parts
	if _, err := uploader.Upload(ctx, &s3.PutObjectInput{Bucket: aws.String("{{bucket}}"), Key: aws.String("code/go.bin"), Body: bytes.NewReader(big)}); err != nil {
		log.Fatal(err)
	}
	got, err := client.GetObject(ctx, &s3.GetObjectInput{Bucket: aws.String("{{bucket}}"), Key: aws.String("code/go.bin")})
	if err != nil {
		log.Fatal(err)
	}
	n, _ := io.Copy(io.Discard, got.Body)
	fmt.Println("read back", n, "bytes")
	list, err := client.ListObjectsV2(ctx, &s3.ListObjectsV2Input{Bucket: aws.String("{{bucket}}"), Prefix: aws.String("code/")})
	if err != nil {
		log.Fatal(err)
	}
	for _, item := range list.Contents {
		fmt.Println(*item.Key, *item.Size)
	}
	link, err := s3.NewPresignClient(client).PresignGetObject(ctx, &s3.GetObjectInput{Bucket: aws.String("{{bucket}}"), Key: aws.String("code/go.bin")})
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println(link.URL)
}
```

## Checking and restoring {#checking}

A backup is only a backup once something was brought back from it. Once a month:

1. Look at what arrived: {{if admin}}in the console{{end}}{{if console}} ({{console}}){{end}}{{if !admin}}ask your administrator, or look{{end}} with `restic snapshots` and `rclone ls` as above. Every machine should have a backup of the last night.
2. Restore one folder and one database into a scratch place, as each section shows, and open a file or count a table.
3. Run `restic check` on each repository: it fails if the repository was damaged or overwritten.
4. Compare the bucket's size (the console's bucket page) with its quota.

Encryption: restic and Kopia encrypt with the repository password before anything leaves the machine; rclone and the plain copies do not (add `rclone crypt` if that matters). Keep the passwords and the keys in your password manager, not only on the machine they protect.

What this protects against: a machine or a website that is broken into can write new files and add "deleted" markers, but it cannot remove or shorten what the lock keeps. It does not protect against this server's disk dying or the house burning: keep a second copy of what matters elsewhere.

## Limits and problems {#trouble}

| You see | Why, and what to do |
| --- | --- |
| `SignatureDoesNotMatch` | the secret is wrong, the region is not `{{region}}`, or the machine's clock is off |
| `RequestTimeTooSkewed` | the machine's clock is more than 15 minutes off: switch on automatic time |
| HTTP 413, "Request Entity Too Large" | a request over 100 MB through the internet address: set your tool's part size (the 64M settings above) |
| `x509: certificate signed by unknown authority`, `CERTIFICATE_VERIFY_FAILED`, `unable to get local issuer certificate` | the home address with a tool that was not given Cosmos' certificate (see Connection settings) |
| `AccessDenied` | the key may not do that: another bucket, deleting a version, creating a bucket (rclone: `no_check_bucket`) |
| `NoSuchBucket` or a name error | the bucket's name, or a client that puts the bucket in front of the address: switch path style on |
| `Could not resolve host` with a `.local` address | this machine does not resolve `.local` names (a VPN, some Android and Windows set-ups): use the internet address, or add the name to the machine's hosts file |
| errors about checksums or `x-amz-checksum` | a 2025 or later SDK: the `when_required` settings above |
| restic: "repository is already locked" | a run was cut off: `restic unlock`, then `restic check` |
| "Bucket quota exceeded" | the bucket is full: raise its quota, or let the lifecycle rule clear old versions |
